# Weekly review

Once a week, read **everything**. Rereading the whole list, work and personal together, is what keeps it trusted: priorities get re-set, dead tasks get deleted, foggy ones get rephrased, and nothing rots quietly in a corner. A list that's been reread this week is one the head can stop checking.

Load the Clear Head config: `~/.clear-head/config.md`, a "Clear Head config" document in the person's connected notes or docs, or the project instructions. Use it for tools, the concept mapping and working rules. If it's missing, offer clear-head-setup, or ask the person to paste their full list and continue.

## Steps

1. **Load.** Pull every open task across all projects, the project list, the calendar for the next 7–14 days, last week's completed tasks, the inbox count and this month's journal.
2. **Inbox.** If items are waiting, offer process-inbox first so they're part of this review. The person may skip it.
3. **Read-through, project by project.** Unfiled tasks first, then each project. For every task propose one outcome:
   - **keep** as is
   - **re-weight or re-date**: change its priority or when
   - **rephrase** with the task-rewriter rules: anything foggy, or untouched for weeks
   - **delete**: no longer matters, already done, or a "should" with no real reason. For doubtful ones, offer a quick so-that-what.

   Show each project as a compact table: task | age | moved count | proposed outcome. Flag tasks that are old or keep moving. The person confirms or edits; apply, then go to the next project. Every open task gets read and gets an outcome: this review is exhaustive by design, so cover every project rather than sampling.
4. **Projects.** For each project:
   - Is it still active? If not, pause or close it.
   - Does it have at least one clear next task? If not, find one with the 20-minute question from task-rewriter. A project with no task is a wish: nothing will move until something is written down.
5. **Last week's wins.** Scan completed tasks for anything needing a follow-up or a next step.
6. **Next week's calendar.** Walk through each event and ask what it needs: prep, travel, something to read, bring, book or send. Turn each answer into a dated task, and apply the checklists skill where one fits (a trip, an appointment). Flag overloaded days and clashes.
7. **Wrap up.** Summarise the changes (deleted, rephrased, re-weighted, new), name the few things that matter most this week, and append a journal entry.

Done when every open task has been read and has an outcome, every active project has a next task, and next week's events have their prep tasks.

If time runs short, a partial review beats a skipped one: finish the project in progress, note in the journal where you stopped, and pick up there next time.
